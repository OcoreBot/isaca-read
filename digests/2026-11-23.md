# Security & Audit Digest — 2026-11-23

## Top items

### 1. China-linked Armory Castle exploited VMware vCenter zero-day (CVE-2026-123890)
**Why it matters for audit/CISO/VAPT:** The virtualization management plane is a high-impact target. Audit should confirm vCenter patch status and review admin logins back to early September.
The suspected China-nexus group Armory Castle (formerly UNC5221) exploited this CVSS 9.8 flaw in September 2026 to gain admin access and steal data. CISA added it to KEV on 2026-11-20, with federal remediation due 2026-11-23. ([source](https://thehackernews.com/2026/11/china-linked-hackers-exploit-critical.html))

### 2. Cisco Expressway hard-coded credential flaw (CVE-2026-76466) exploited shortly after PoC release
**Why it matters for audit/CISO/VAPT:** Edge collaboration appliances are a common lateral-movement entry point. VAPT should prioritise exposure checks.
Attackers breached four Expressway devices at a Russian organization and reached the internal network soon after a public PoC appeared. The flaw is in KEV, with a federal due date of 2026-11-23. ([source](https://thehackernews.com/2026/11/hackers-exploit-critical-cisco.html))

### 3. CISA adds four flaws to KEV: SAP NetWeaver, Cisco Expressway, Apache Roller, VMware vCenter
**Why it matters for audit/CISO/VAPT:** This is the authoritative list for patch-SLA evidence. Map it against the asset inventory.
The additions are CVE-2025-42884 (SAP NetWeaver), CVE-2026-76466 (Cisco Expressway), CVE-2026-129448 (Apache Roller deserialization) and CVE-2026-123890 (vCenter). All were added 2026-11-20. ([source](https://www.cisa.gov/news-events/alerts/2026/11/20/cisa-adds-four-known-exploited-vulnerabilities-catalog))

### 4. GL.iNet cloud management flaw used to backdoor routers and KVM devices
**Why it matters for audit/CISO/VAPT:** Cloud-managed edge and out-of-band KVM devices often sit outside asset inventories.
Attackers abused GL.iNet's cloud remote-management service to install malware, with reverse shells reported. SANS notes a disguised process (`crond -i /tmp/.log`) as an indicator. GL.iNet blocked the cloud path and recommends a factory reset. ([source](https://www.bleepingcomputer.com/news/security/hackers-exploit-glinet-cloud-flaw-to-infect-routers-kvm-devices/))

### 5. Ghostscript sandbox-escape RCE (CVE-2026-125396, "Upload2Shell")
**Why it matters for audit/CISO/VAPT:** Ghostscript is a hidden dependency in upload and image pipelines, which makes it a classic audit finding. VAPT should test document-conversion endpoints.
A use-after-free in the Type 1 font loader lets a crafted file escape `-dSAFER` and run commands on servers that convert uploads. It is fixed in Ghostscript 10.08.0. ([source](https://thehackernews.com/2026/11/researchers-demonstrate-ghostscript.html))

### 6. Microsoft confirms Entra Connect Health flaw exploited to steal tenant data
**Why it matters for audit/CISO/VAPT:** Identity-sync tooling sits in the trust path to cloud tenants. Review tenant configuration and admin-contact integrity.
Attackers exploited a vulnerability in Entra Connect Health to access administrator email addresses and tenant configuration information. ([source](https://www.bleepingcomputer.com/news/security/microsoft-entra-connect-health-flaw-exploited-to-steal-tenant-data/))

### 7. Rackspace Spot breach exposed customer Kubernetes secrets
**Why it matters for audit/CISO/VAPT:** This is a clear shared-responsibility case study. Customers should rotate cluster secrets and review workload audit logs.
Attackers used compromised credentials to deploy unauthorized workloads and read Kubernetes secrets in customer clusters. ([source](https://www.bleepingcomputer.com/news/security/rackspace-spot-breach-let-hackers-access-customer-kubernetes-secrets/))

### 8. Linux KVM flaw (CVE-2026-99312) lets guest VMs read host memory on AMD hosts
**Why it matters for audit/CISO/VAPT:** It is a cross-tenant isolation failure, relevant to cloud-provider due diligence and hypervisor patch tracking.
Researchers read about 127 GB of host memory from their own VM on a DigitalOcean AMD server. On shared hosts this can expose other tenants' VMs. ([source](https://thehackernews.com/2026/11/new-linux-kvm-flaw-cve-2026-99312-lets.html))
